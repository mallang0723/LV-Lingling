령령(봇카드)과 대화하며 **캐릭터·페르소나·로어북(월드북)** 을 만들고, 고치고, 루미버스에 저장하는 확장입니다. 제작·수정 요청을 지금 열려 있는 채팅(령령 방)에 보내고, 령령의 마지막 답변을 읽어 와 편집 화면에 반영합니다.

## 쓰는 법 (요약)

1. [령령 카드를 가져오고](#령령-카드-가져오기) 페르소나 이름을 `{{user}}`로 맞춘 뒤, **령령과의 1:1 채팅**을 엽니다.
2. 화면 오른쪽 아래의 **유령 버튼**(끌어서 옮길 수 있어요)을 누르면 제작실 창이 열립니다. 창은 머리줄을 끌어 옮기고, 데스크톱에서는 오른쪽 아래 모서리로 크기를 바꿉니다. 폰처럼 좁은 화면(폭 640px 이하)에서는 전체 화면으로 열려요.
   - 유령 버튼 말고도 사이드바의 **령령의 제작실** 탭, 입력창 ➕(Extras) 메뉴의 **령령의 제작실**, `Ctrl+K` 팔레트("령령")로 열 수 있어요.
3. 창 왼쪽 위의 **사람·가면·책 아이콘**으로 캐릭터 / 페르소나 / 로어북 제작실을 고릅니다.
4. **1 준비** — 자유 제작 · 기존 자료 참고 · 기존 항목 편집 중에서 고르고 구상을 적은 뒤 **령령에게 바로 요청**. (참고 자료: 기존 캐릭터·페르소나·월드북 항목 최대 3·3·1개, 또는 외부 문서 최대 5개 — 팬덤 위키 링크 또는 붙여넣기)
5. **2 제작** — 령령과 채팅으로 다듬고, 형식(마크다운/서술형)·분량을 골라 **최종본 바로 요청**. 령령 답변이 끝났다는 알림이 뜨면 **마지막 AI 답변 가져오기**.
6. **3 편집** — 가져온 항목을 직접 고치거나 **부분 수정 요청**을 보내고 **마지막 답변 가져오기**(또는 직접 붙여넣기). 이전/복원으로 되돌릴 수 있어요.
7. **4 최종** — **새 항목으로 등록**하거나 편집 모드에서는 **원본에 저장**. JSON 파일 저장·전체 복사도 됩니다.

## 령령 카드 가져오기

원작 릴리스의 `CharCard.json`은 **Marinara 내보내기 형식**(`{"type":"marinara_character", …, "data": {"spec":"chara_card_v2", …}}`)이라 Lumiverse 1.2.5에 그대로 가져오면 실패합니다. Lumiverse의 가져오기는 파일 **맨 위**에서 `spec: "chara_card_v2"`를 찾는데(`parseCardJson`), 이 파일은 한 겹 감싸여 있어서 "Character card is missing required 'name' field"가 납니다. ✅ 호스트 소스(v1.2.5)에서 확인.

그래서 포함된 변환 스크립트로 한 겹 벗깁니다(Node 18+, 외부 패키지 없음, 원본 파일은 안 건드려요):

```sh
node scripts/convert-card.mjs /경로/CharCard.json            # 같은 폴더에 두 파일을 씀
#   CharCard.lingling.png     ← 이걸 가져오세요 (카드 + 령령 아바타 + 내장 로어북)
#   CharCard.lumiverse.json   ← 아바타 없이 카드·로어북만 (PNG가 안 될 때)
```

1. 루미버스 **캐릭터 → 가져오기**에서 `CharCard.lingling.png`(또는 `.lumiverse.json`)를 고릅니다.
2. 가져오면 **내장 로어북 "령령 명령어"(5개: `@TTS` `@삽화` `@그뽑` `@상태창` `시뮬`)** 가 월드북으로 자동 가져와져 그 캐릭터에 붙습니다(Lumiverse가 카드의 `character_book`을 가져올 때 하는 일). 월드북 목록에서 확인하세요.
3. **캐릭터 이름이 `{{char}}`인 것은 정상이에요.** 원작 카드가 일부러 그렇게 되어 있고, 확장이 `{{char}}`·`{{user}}`를 원문 그대로 주고받게 만들어져 있습니다. Lumiverse의 가져오기는 이름이 비어 있지만 않으면 받아 줍니다(✅ 소스 확인). 매크로 엔진은 `{{char}}`가 자기 자신으로 풀리면 "Recursive macro expansion detected"라는 진단을 남기고 `{{char}}`를 글자 그대로 둡니다(✅ 소스 확인, ⚠️ 실서버 동작은 미확인). 이름을 바꾸지 마세요 — 바꾸면 령령이 만든 필드 속 `{{char}}`가 실제 이름으로 풀려 카드 이식성이 깨집니다.
4. **페르소나 이름을 `{{user}}`로** 만듭니다(원작의 요구사항). 루미버스 **페르소나**에서 새 페르소나를 만들고 이름 칸에 `{{user}}`를 그대로 적은 뒤 그 페르소나를 쓰는 상태로 령령 방을 여세요. 이름이 진짜 이름이면 호스트가 `{{user}}`를 그 이름으로 바꿔 모델에 보내서, 령령이 만드는 필드에 실제 이름이 들어갑니다.
5. 령령 카드와 **새 1:1 채팅**을 시작합니다. 확장은 "지금 열려 있는 채팅"으로 요청을 보내요. 그 방의 캐릭터 이름이 `{{char}}`가 아니면 사이드바 탭에서 경고를 보여 줍니다(막지는 않아요).

추가 이미지(`LinglingImage.zip`, 38장)는 원작 릴리스에서 받아 압축을 풀어 쓰세요. 확장과 상관없는 그림 모음입니다.

## 설치

1. Lumiverse 1.2.5 이상, **관리자 계정**으로 확장 패널에서 이 폴더를 로컬 설치합니다. `dist/`가 들어 있어 따로 빌드할 필요가 없어요.
2. 권한을 허용합니다(이 확장이 쓰는 곳):

   | 권한 | 쓰는 곳 |
   |---|---|
   | `characters` | 참고 캐릭터 읽기, 새 캐릭터 등록, 원본 캐릭터에 저장 |
   | `personas` | 참고 페르소나 읽기, 새 페르소나 등록, 원본 페르소나에 저장 |
   | `world_books` | 참고 월드북·항목 읽기, 새 월드북 등록, 원본 월드북에 저장 |
   | `chats`, `chat_mutation` | 지금 열린 채팅 확인, 요청 메시지 넣기, 령령의 마지막 답변 읽기 |
   | `generation` | 요청 메시지를 넣고 령령의 답변 생성 시작, 생성 시작·끝 알림 |
   | `interceptor` | **상시 주입**(참고 자료·현재 초안을 령령 방의 새 답변에 계속 전달) |
   | `ui_panels` | 떠 있는 유령 버튼과 창. **없어도 동작**: 사이드바 탭 안에서 제작실이 열립니다 |

3. 사이드바의 **령령의 제작실** 탭에서 연결(요청에 쓸 AI 연결)과 저장 옵션을 고릅니다(바꾸는 즉시 저장).

직접 빌드하려면 Bun 1.4.0이 필요합니다: `BUN_BIN=/경로/bun npm run build`.

## 기능 매핑 (Marinara → Lumiverse)

| 원작 (Marinara) | 이식판 (Lumiverse) |
|---|---|
| 화면 오른쪽 아래 유령 버튼 / 끌어서 옮기는 창 | `ui_panels` 떠 있는 위젯 2개(버튼·창). 위치는 호스트가 기억. 머리줄만 끌려서 옮겨지고 본문 스크롤과 겹치지 않음. 폭 640px 이하는 전체 화면, 데스크톱은 크기 조절 모서리. 권한이 없으면 사이드바 탭 안에서 열림. 사이드바 탭·입력창 Extras·`Ctrl+K`로도 열기 |
| 캐릭터·페르소나·로어북 제작실, 1~4단계, 자유/참고/편집 모드, 외부 자료, 키워드, 토큰 추정, 이전/복원 | 원작의 화면 조각과 문구를 그대로 옮김(`src/original/ui.js`) |
| 요청문(브리핑·최종본·부분 수정)·출력 계약·응답 해석·매크로 보호 | 원작 코드를 그대로 옮김(`src/original/logic.js`). `[MARINARA_…]` 표식과 `<<<MARINARA_…>>>` 패킷도 원문 그대로 — 령령 카드가 이 글자로 작업을 알아봄 |
| RP 입력창에 요청을 채우고 전송 버튼을 클릭 | `chat.appendMessage(…, { triggerGeneration })` 로 지금 열린 채팅에 사용자 메시지로 넣고 령령 답변 생성 시작(`generation` 필요). 요청 본문은 원작처럼 한 줄 라벨 + 숨김 블록으로 감쌈. 채팅 입력창에 **채워만 넣기**는 호스트에 `ctx.composer`가 있을 때만 버튼이 나타남(1.2.5에는 없음) |
| 마지막 AI 답변 가져오기 (`GET /api/chats/:id/messages?limit=1`) | `chat.getMessages` 의 마지막 메시지 1개. 마지막이 사용자 메시지·일반 대화·다른 제작실 결과면 원작처럼 가져오지 않음. 생성 중이면 막고, 령령 답변이 끝나면 알림 |
| 참고 자료 상시 주입 / 현재 프롬프트·로어북 상시 주입 (`/api/generate`의 fetch를 가로채 `generationGuide`에 덧붙임) | `registerInterceptor`: 프런트가 만든 본문을 채팅별로 백엔드에 등록해 두고, 새 답변을 만들 때 마지막 사용자 턴 앞에 시스템 메시지로 넣음. 원작처럼 이어쓰기·다시 생성·대신 쓰기·스와이프와 이미 제작실 계약이 든 요청은 건너뛰고, 캐릭터·페르소나 최종본 요청에는 참고 자료만 넣음 |
| 임시 저장 / 초기화 (확장 저장소) | 사용자 저장소 `studio.json`(원작과 같은 키 `rpCharacterStudioDraftV1` 등). 제작실 전환·닫기·임시 저장 버튼에서 저장 |
| 캐릭터 등록·원본 저장 (`POST/PATCH /api/characters`) | `characters.create/update`. 원본 저장은 원작처럼 바뀐 필드만 보내고, 불러온 뒤 다른 곳에서 바뀐 필드가 있으면 충돌을 알림. `extensions`는 호스트가 얕게 합치므로 우리 이름공간(`lingling_studio_lv`)만 보냄(`world_book_ids` 등 다른 키가 안 지워짐) |
| 페르소나 등록·원본 저장 | `personas.create/update`. `metadata`는 통째로 바뀌는 API라 다른 확장의 메타데이터를 읽어 합쳐서 씀 |
| 로어북 등록·원본 저장 (Entry 수정·추가·삭제·순서·폴더, 중간 실패 복구 안내, 저장 뒤 다시 읽어 검증) | `world_books.create/update` + `entries.list/create/update/delete`. 원작의 저장 절차(`$n`)를 코드 그대로 쓰고 사이에 어댑터(`src/host.js`)만 둠. 페이지네이션(200개씩)·`userId`는 백엔드에서 처리 |
| JSON 파일 저장·전체 복사 | 캐릭터·로어북은 **Lumiverse가 가져올 수 있는 형식**(`chara_card_v2` / `{name, description, entries}`)으로. 페르소나는 원작의 여섯 필드 JSON 그대로. 복사는 `navigator.clipboard`가 없는 http(폰)에서도 되도록 숨은 입력칸 복사로 대체 |
| 모델 연결 | 원작은 방에 설정된 AI. 여기서는 기본은 채팅의 연결이고, 사이드바 탭에서 "령령에게 보낼 때 쓸 연결"을 고르면 `generation.connection_id`로 넘김(고르는 즉시 저장) |

## 옮기지 못한 것 / 달라진 것

**루미버스에 자리가 없어서**

- **캐릭터의 배경 이야기·외모·Convo 표시 이름·About Me·Convo 행동 지시** — Lumiverse 캐릭터에는 이 칸이 없습니다(호스트 소스에 이 키를 읽는 곳이 없음). 그래서 저장할 때 **배경 이야기·외모는 `description` 뒤에 `## 배경 이야기` / `## 외모` 절로 합쳐** RP 프롬프트에 들어가게 하고(사이드바 탭에서 끌 수 있음), 다섯 칸 전부를 캐릭터의 `extensions.lingling_studio_lv`에도 보관합니다. 같은 캐릭터를 제작실에서 다시 불러올 때 합친 글이 그대로면 보관한 값으로 칸을 되살리고, 루미버스 쪽에서 설명을 고쳤다면 **보관본을 믿지 않고 설명 전체를 "설명" 칸에 넣습니다**(배경·외모 칸은 비어서 옴). Convo 세 칸은 루미버스에서 어디에도 쓰이지 않습니다(보관만).
- **페르소나의 성격·배경 이야기·외모·시나리오** — Lumiverse 페르소나는 이름·제목·설명뿐입니다. 위와 같은 방식으로 **설명에 절로 합치고**(`## 성격` 등) `metadata.lingling_studio_lv`에 여섯 칸을 보관합니다. 페르소나 JSON 파일은 원작 형식 그대로라 루미버스가 바로 가져오지는 못합니다(제작실 안에서 등록하세요).
- **로어북 Entry의 "설명"** — 월드북 Entry에는 별도 설명 칸이 없어 Entry의 `extensions.lingling_studio_lv.description`에 둡니다(루미버스 화면에는 안 보임). 타입은 normal / constant / selective → `constant`·`selective` 플래그로 옮기고, 선택 조건의 보조 키·논리는 건드리지 않습니다(바뀐 칸만 보내므로 보존). 보조 키가 없는 selective는 호스트가 일반 키워드 항목처럼 다룹니다(✅ 소스 확인).
- **로어북 폴더** — Lumiverse 월드북에는 폴더 개체가 없습니다. 원작이 폴더를 복사하던 부분은 도달하지 않습니다(읽을 때 폴더 없음으로 돌려줌).
- **채팅 입력창에 요청 채우기** — 1.2.5에는 입력창 API가 없습니다. 그래서 "RP 입력창에 넣기" 버튼은 `ctx.composer`가 있는 호스트에서만 보이고, 없으면 **복사**와 **령령에게 바로 요청**을 씁니다.
- **아바타·색상·스탯** — 원작도 페르소나 JSON에는 안 담았습니다(Marinara 전체 내보내기 사용). 여기서도 다루지 않습니다.

**호스트 동작 때문에 ⚠️ 실서버에서 확인하지 못한 것 (스텁 호스트로만 검증)**

- 요청 메시지 숨김: 원작이 쓰던 `<span class="csm-studio-command">라벨</span>` + `display:none` 블록에, 빈 줄이 HTML 블록을 끊지 않도록 `<lingling-studio-request>` 태그를 한 겹 더 두르고 프런트가 메시지 태그 가로채기(`removeFromMessage`)로 렌더에서 지웁니다. 루미버스의 sanitizer(DOMPurify)가 `style`을 남기는 것은 소스로 확인했지만, 실제 화면에서 라벨만 보이는지는 못 봤어요. 안 숨겨지면 요청 전문이 채팅에 보일 뿐 동작은 같습니다.
- 확장이 넣는 사용자 메시지의 이름: 호스트가 `name: "User"`로 저장합니다(문서는 페르소나 이름이라고 하지만 1.2.5 코드는 고정). 프롬프트 조립에는 영향이 없을 것으로 보이나(⚠️) 채팅 화면에는 "User"로 보일 수 있어요.
- 인터셉터가 돌려주는 `{ messages, breakdown }`, 메시지 태그 가로채기, 떠 있는 위젯의 `touchScrollMode`·`setFullscreen`은 호스트 소스(v1.2.5)에서 시그니처를 확인했지만 실서버에서 돌려 보지는 못했습니다.

## 저장되는 데이터

- 초안·임시 저장: 확장 사용자 저장소 `studio.json`(사용자별), 설정(`settings.json`: 연결, 합쳐 저장 여부).
- 루미버스 캐릭터/페르소나/Entry에는 우리 이름공간 `lingling_studio_lv`로 위 보관본이 붙습니다.
- 팬덤 위키 링크 불러오기는 브라우저가 팬덤의 공개 문서 API에 직접 요청합니다(원작 그대로: HTTPS, 쿠키 없음, 문서당 60KB·전체 110KB 제한).
- 모델에 가는 것: 사용자가 보낸 요청, 그리고 **상시 주입을 켠 동안** 참고 자료와 현재 초안.
